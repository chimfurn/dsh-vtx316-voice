# dsh-vtx316-voice

[中文](#中文) | [English](#english)

通过串口让 [DeepSeek Harness](https://github.com/deepseek-ai) 里的模型操作
**宇音天下 VTX316** 中文语音合成模块说话、读取模块参数。

A DSH (DeepSeek Harness) Host plugin that gives the model two tools for an
**宇音天下 (VoiceTX) VTX316** speech-synthesis module over a serial port:
speak text aloud and read the module's current TTS parameter block.

## 中文

### 功能

| 工具 | 作用 |
|---|---|
| `vtx316_speak` | 把文本转成 GBK，按 VTX316 帧格式发送到串口朗读；默认等待模块回传 `0x4F`（播放完成），并返回 `0x41`/`0x45` 等反馈 |
| `vtx316_get_params` | 发送 `FD 00 01 05`，解析 `0x5F` + 17 字节参数回传（编码、语速、音量、语调、发音人、提示音开关、风格、读法开关、英文读法） |

`vtx316_speak` 参数：`text`（必填）、`volume`(0-10)、`speed`(1-30)、`tone`(0-10)、
`wait`（默认 true）、`timeoutMs`。省略音量/语速/语调时使用配置里的默认值；
调用会串行执行，多句不会互相打断。

### 串口协议

```
帧：FD | 数据区长度高 | 数据区长度低 | 命令字 | 命令参数 | 数据
语音合成：FD 00 (文本GBK字节数+2) 01 01 <GBK文本>
获取参数：FD 00 01 05   →   回传 0x5F + 17 字节参数块
```

模块默认 115200 8N1（BAUD0/BAUD1 悬空）。本插件不依赖任何 npm 包，串口通过
Windows 自带的 PowerShell（`System.IO.Ports.SerialPort`）访问。

### 配置

编辑 [`cordis.patch.yml`](cordis.patch.yml) 中插入的插件行：

```yaml
- insert:
    - id: vtx316-voice
      name: dsh-vtx316-voice
      config:
        port: COM6            # 模块所在串口
        baud: 115200
        defaultVolume: 1      # 缺省音量，省略参数时下发 [v1]
        defaultSpeed: 23      # 缺省语速，下发 [s23]
        defaultTone: 9        # 缺省语调，下发 [t9]
```

### 安装

1. 把本目录放到任意位置；
2. 在 DSH 中通过 **plugin_manager → install_bundle** 选择该目录安装（profile 级，
   安装后重启 Harness 生效）；或使用命令行：

   ```powershell
   dsh plugin --profile desktop add link:<repo目录>
   ```

3. 安装后模型会看到 `vtx316_speak` 与 `vtx316_get_params` 两个工具。

### 已知限制（官方资料 + 实测）

- **仅支持 Windows**：依赖 Windows PowerShell 的串口 API。
- **VTX316 不支持英文合成**：官方《语音合成芯片_功能对比》中 VTX316 的“英文合成”为 `-`，
  用户手册写明“遇到英文单词时按字母方式发音”；`[g*]`/`[h*]` 是中英合成芯片的标记，
  VTX316 不解析（实测发送后参数回读不变）。需要英文单词发音时请用中文音译
  （如 `DeepSeek → 迪普希克`），型号/缩写（`STM32`、`VTX316`）按字母读本来是正确的。
- **供电**：模块由 USB-TTL 供电时音量开大可能掉电复位（表现为等不到 `0x4F`），
  建议音量 ≤5；需要大声请给模块独立 5V 并共地。

## English

### Features

| Tool | Purpose |
|---|---|
| `vtx316_speak` | Encode text as GBK, send a VTX316 synthesis frame over serial and (by default) wait for the module's `0x4F` playback-finished feedback; reports `0x41`/`0x45` too |
| `vtx316_get_params` | Send `FD 00 01 05` and parse the `0x5F` + 17-byte TTS parameter block (encoding, speed, volume, tone, speaker, prompt-sound switch, style, reading switches, English settings) |

`vtx316_speak` arguments: `text` (required), `volume` (0-10), `speed` (1-30),
`tone` (0-10), `wait` (default true), `timeoutMs`. Omitted volume/speed/tone use
the configured defaults. Calls are serialized so utterances never interleave.

### Protocol

```
Frame: FD | data-length high | data-length low | command | parameter | data
Speak:    FD 00 (gbkTextBytes+2) 01 01 <GBK text>
Params:   FD 00 01 05   →   0x5F + 17 parameter bytes
```

The module runs 115200 8N1 by default (BAUD0/BAUD1 floating). No npm dependency:
the serial port is accessed through the Windows PowerShell that ships with Windows.

### Requirements & install

- Windows (uses `System.IO.Ports.SerialPort` via Windows PowerShell).
- Put this directory anywhere and install it with DSH **plugin_manager →
  install_bundle** (profile-level; restart the Harness after installing), or:

  ```powershell
  dsh plugin --profile desktop add link:<path-to-this-repo>
  ```

### Configuration

See the row in [`cordis.patch.yml`](cordis.patch.yml): `port`, `baud`,
`defaultVolume`, `defaultSpeed`, `defaultTone`.

### Known limitations

- Windows only.
- The VTX316 is a **Chinese-synthesis** chip; English words are always spelled
  letter by letter (official feature comparison marks English synthesis as not
  supported, and the `[g*]`/`[h*]` control markers belong to Chinese+English
  chips and are not parsed by VTX316). For English words that must sound like
  the word, write a Chinese phonetic approximation (e.g. `DeepSeek → 迪普希克`);
  uppercase model numbers/acronyms are correctly read as letters.
- When powered from a USB-TTL adapter keep the volume at 5 or below; louder
  playback can brown out the serial supply (the module stops acknowledging).
